# 지원 범위와 제한

## 지원 범위

| 기능 | 범위 |
| --- | --- |
| 열기 | Chrome 이 PDF 로 판단한 문서. 한 번에 한 쪽씩 표시 |
| 선택·검색 | 추출 가능한 글자. 스캔 이미지 속 글자는 선택·검색되지 않습니다(OCR 없음) |
| 문단 편집 | 선택한 문단을 그 영역 안에서 다시 배치. 영역 밖 문단을 밀어내지 않고, 쪽을 넘기지 않습니다 |
| 표 셀 편집 | 기존 셀의 텍스트 수정(셀 하나가 편집 단위). 행·열 추가, 병합·분할 없음 |
| 벡터 편집 | 판정을 통과한 패스의 이동·크기, 점 이동, 선 두께, 채움·선 색, 삭제, 다중 선택. 새 패스 그리기, 차트 데이터 수정 없음 |
| 지원하지 않음 | 이미지 내용 편집, 폼·서명, 협업, 연속 스크롤 보기, 글자쌍 커닝 보존 |

## 편집할 수 없는 경우와 사유

편집할 수 없는 문단·셀·패스에는 사유가 표시됩니다(더블클릭 팝오버, "레이아웃·편집 표시"의 툴팁). 사유는 아래와 같습니다.

### 글자(문단·셀)

| 표시 문구 | 풀어 쓴 뜻 |
| --- | --- |
| 세로쓰기·회전된 글자는 편집할 수 없습니다 | 세로쓰기이거나 회전된 글자 |
| 원본 글자를 안전하게 지울 수 없는 연산이 있어 편집할 수 없습니다 | 원본 글자를 주변 손상 없이 지울 수 없는 PDF 구조 |
| 문단 글자가 쪽 본문과 별도 개체(Form)에 걸쳐 있어 편집할 수 없습니다 | 한 문단이 본문과 Form 에 나뉘어 있음 |
| 대체 텍스트(ActualText)의 일부만 지우게 되어 편집할 수 없습니다 | 대체 텍스트의 일부만 지우게 되는 경우 |
| 글자가 놓인 좌표 변환이 특이 행렬이라 편집할 수 없습니다 | 글자 좌표 변환이 퇴화한 경우 |
| 글자 위치가 잘림 영역(클립)에 가려져 편집할 수 없습니다 | 새 글자가 클립에 가려짐 |
| 글자 개체를 나눌 수 없는 구조(클립 텍스트 등)라 편집할 수 없습니다 | 글자 개체(BT)를 나눌 수 없음 |
| 투명도 마스크·패턴 채움이 달라 새 글자를 같은 모양으로 쓸 수 없습니다 | 새 글자를 같은 모양으로 그릴 수 없음 |
| 원본 PDF 의 글자 연산과 연결하지 못해 편집할 수 없습니다 | 화면의 글자와 PDF 내부 연산을 대응시키지 못함 |
| 콘텐츠 스트림을 해석하지 못해 편집할 수 없습니다 | 쪽 내용 해석 실패 |
| 글자 연산이 콘텐츠 스트림 경계에 걸쳐 있어 편집할 수 없습니다 | 연산이 스트림 경계에 걸침 |
| 개체(Form)가 자체 리소스가 없어 편집할 수 없습니다 | Form 이 글꼴 등을 쪽에서 상속 |
| 쪽 본문 밖(주석 외관·패턴·Type3 글리프·SMask 안)의 글자는 편집할 수 없습니다 | 쪽 본문이 아닌 곳의 글자 |
| 개체(Form) 중첩이 너무 깊어 편집할 수 없습니다 | Form 중첩 8단계 초과 또는 순환 |
| Type3 글꼴은 편집할 수 없습니다 | 비트맵·도형 글꼴 |
| 글꼴 인코딩을 복원하지 못해 편집할 수 없습니다 | 글자 코드와 문자를 대응시키지 못함 |
| 클립 텍스트(렌더 모드 4–7)는 편집할 수 없습니다 | 글자를 클립으로만 쓰는 경우 |
| 보이지 않는 글자(스캔 문서의 OCR 층)는 편집할 수 없습니다 | 투명 글자 층 |
| 인라인 이미지가 섞여 있어 편집할 수 없습니다 | 글자 사이에 인라인 이미지 |

다음 항목은 편집은 되지만 안내 또는 경고가 나옵니다.

| 표시 문구 | 뜻 |
| --- | --- |
| 태그된 구조 안의 글자입니다 / 태그된 PDF 입니다. 구조(읽기 순서·태그)는 갱신하지 않습니다 | 편집은 되나 읽기 순서·태그 구조는 갱신되지 않음. 설정으로 태그 쪽 편집을 막을 수 있음 |
| 새 글자가 개체(Form) 영역을 벗어납니다 | 새 글자가 Form 영역보다 커져 일부가 잘릴 수 있음 |
| 선택적 콘텐츠(레이어) 안의 글자입니다 | 레이어 안의 글자 |

### 벡터 패스

| 표시 문구 | 뜻 |
| --- | --- |
| 잘림 영역(클립)을 만드는 패스는 편집할 수 없습니다 | 클립을 정의하는 패스 |
| 무늬(패턴)·그러데이션(셰이딩) 채움 패스는 편집할 수 없습니다 | 패턴·셰이딩 채움 |
| 패스 그리기 연산을 해석하지 못해 편집할 수 없습니다 | 해석 실패 |
| 패스가 콘텐츠 스트림 경계에 걸쳐 있어 편집할 수 없습니다 | 스트림 경계에 걸침 |
| 글자 개체(BT) 안의 패스는 편집할 수 없습니다 | 글자 개체 안에 있는 패스 |
| 패스 그리기 도중에 다른 연산이 끼어 있어 편집할 수 없습니다 | 연산이 섞여 있음 |
| 투명도 마스크(SMask) 아래의 패스는 편집할 수 없습니다 | 소프트 마스크 아래 |

### 편집 후 경고

| 경고 | 뜻 |
| --- | --- |
| 폴백 글꼴 사용(`font-fallback`) | 원본 글꼴에 없는 글자를 대체 글꼴로 씀 |
| 영역 초과(`overflow-clipped`) | 상한까지 늘려도 넘쳐 일부가 잘릴 수 있음 |
| 합성 스타일(`synthetic-style`) | 굵게·기울임을 합성으로 표현 |
| 색 공간 변경(`color-space-changed`) | 예: 회색 패스에 RGB 색 지정 |
| 클립에 잘림(`path-clipped`) | 이동한 패스가 클립에 가려짐 |
| 표 괘선 삭제(`table-rule-removed`) | 표 격자 선을 지움 |

## 문서 크기 상한

- 편집한 문서는 저장할 때 문서 전체를 다시 쓰며, 브라우저의 WASM 메모리 상한(2 GiB) 안에서 처리됩니다. 출력은 스트리밍되지 않습니다.
- 지원 문서 크기는 약 790 MiB 입니다(이미지 위주 문서를 열자마자 편집 후 저장하는 경우 기준). 이보다 큰 파일은 열 때 "편집·저장이 실패할 수 있음" 알림이 나오며, 열람은 됩니다.
- 저장 전에 파일 크기·객체 수·스트림 크기·편집 기록으로 예상 메모리를 계산해, 2 GiB 의 75%(1,536 MiB)를 넘으면 경고(확인 창)하고 2 GiB 를 넘으면 저장하지 않고 안내합니다(`docs/m5-heap.md` 3·4.4·6절).
- 작업 메모리는 저장 뒤 줄지 않지만 다음 저장이 그 빈 공간을 다시 씁니다. 같은 문서를 두 번째 저장할 때 예상은 첫 저장과 비슷하게 계산됩니다.
- 2 GiB 를 넘는 예상의 주된 이유가 이미 커진 작업 메모리(앞선 저장·쪽 보기)이면 저장을 막지 않고 "그래도 저장 시도" 를 고를 수 있습니다. 실패하면 작업 모듈을 복구하고 다시 저장할지 묻습니다.
- 저장을 막은 경우 저장하지 않은 편집은 남아 있습니다. 파일을 다시 열면 메모리가 정리되지만 저장하지 않은 편집은 사라집니다.
- 이미지가 많거나 객체 수가 많은 문서는 파일 크기가 작아도 저장 때 메모리를 더 쓸 수 있습니다.
- 편집 기록(되돌리기용)도 메모리를 차지합니다. 편집을 마칠 때마다 편집 기록과 예상 저장 메모리를 합쳐 경고선(1,536 MiB)을 넘으면 "먼저 저장하고 파일을 다시 열기" 알림이 나옵니다. 다시 연 뒤에는 이전 편집을 되돌릴 수 없습니다.
- 상한 근처 문서에서 저장이 실패하면 작업 모듈을 복구하고 다시 저장할지 묻습니다.

## 되돌리기 이력이 사라지는 경우

- 저장 직후의 첫 되돌리기 등 일부 조건에서는 다시 실행(redo) 이력이 사라질 수 있습니다(`docs/m3-integration.md` 7절 #4).
- 저장 중 작업 모듈이 중단되어 복구된 뒤에는 되돌리기 이력이 사라집니다. 편집 내용 자체는 복구됩니다("복구 전 되돌리기 이력은 사라졌습니다" 안내).
- 패스 편집을 시작한 뒤 갱신하고 취소하면 다시 실행 이력이 사라집니다. 갱신 없이 취소한 경우에는 유지됩니다.

## 알려진 제한

| 항목 | 내용 |
| --- | --- |
| 글자쌍 커닝 | 편집한 줄 안의 글자 간격이 원본과 조금 다를 수 있습니다 |
| 일부 표 | 같은 기준선에서 떨어진 조각이나 여러 열을 묶은 셀은 편집 시 글자가 최대 수 pt 이동하거나 표 모양 확인에 실패할 수 있습니다 |
| 셀 넘침 | 셀 안에서 한글을 덧붙여 셀 상한을 넘으면 넘친 줄이 잘리고 경고가 나옵니다 |
| Alt+클릭 응답 | 쪽을 연 직후나 패스 편집 직후에는 편집 가능 판정이 끝날 때까지 선택 상자가 나타나지 않습니다(서버 약 0.1 초). 그동안의 Alt+클릭은 판정 뒤 반영되므로 다시 누르지 않아도 됩니다 |
| 쪽 판정 시간 | 패스가 매우 많은 쪽은 처음 진입할 때 편집 가능 판정에 약 1.05 초(코퍼스 최대 패스 쪽, 서버 콜드 중앙값), 다시 들어갈 때 약 0.3 초가 걸립니다. Windows 측정 전입니다 |
| 키보드 접근성 | 패스 선택·이동을 키보드로 할 수 없습니다 |
| Redact 주석 | 적용되지 않은 Redact 주석은 적용하지 않습니다 |

## English summary

- Scope: single-page view, text selection and search, paragraph and table-cell text editing (inside the edit area), vector path editing. Not supported: OCR, image editing, forms/signatures, row/column insertion, continuous scroll.
- Content that cannot be edited shows a reason: vertical or rotated text, Type3 fonts, unresolved font encodings, clip text, invisible OCR text, content outside the page body, patterns/shadings, clip paths, soft masks, and structures the editor cannot safely rewrite.
- Saving rewrites the whole file within a 2 GiB WASM memory limit. The viewer estimates the save peak from file size, object count, stream sizes and edit history; it asks for confirmation above 1,536 MiB and refuses above 2,048 MiB. Supported document size is about 790 MiB (image-heavy document, edited and saved right after opening); larger files show a notice on open. When the estimate is high mainly because working memory already grew (an earlier save or page views), the viewer offers "save anyway" instead of refusing.
- Redo history can be lost right after a save or after crash recovery; undo history is lost after recovery.

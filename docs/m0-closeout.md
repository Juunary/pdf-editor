## 2. M0 에서 확정된 기술 사실

| # | 사실 | 근거 |
|---|---|---|
| 1 | 한글 폴백은 glyf TTF 서브셋. CFF OTF 는 MuPDF 1.28.1 `addFont` 경로에서 표시·서브셋 실패 | Day 1 6.3, PLAN.md v2.1 |
| 2 | `canBeSavedIncrementally()` 는 권고값. MuPDF 는 증분 저장을 막지 않아 지운 원문이 남음 → 텍스트 교체는 항상 전체 저장 | Day 1 6.4 |

| 5 | 공유 Form 은 편집 위치만 새 인스턴스로 교체(임시 페이지 redaction) | DoD 1절, 코퍼스 2.9 |

## 5. 일정 재산정

M0 는 계획 3주 대신 2일에 끝났다. 실제 코퍼스·Windows 검증에서 나온 작업을 해당 마일스톤에 더해 M1–M5 를 다시 잡는다. 기준일은 M1 시작일 2026-10-19(월)이다.

|---|---|---|---|---|
| M0 | 3주 | 완료(2일) | 2026-10-18 ~ 10-19 | — |
| M1 추출·원본 연결 | 3주 | **4주** | 2026-10-19 ~ 11-15 | 텍스트 선택 층·Ctrl+F(Windows 알려진 한계), 계약 V3·V5 정정과 MuPDF 전달 시점 에뮬레이션(실측 불일치), 폴백 폰트만 서브셋(A7-1), 텍스트 제거 경로 결정(A7-2), 사각형 정규화(A7-3), 가로채기 경계·DNR object(A5-1·A5-2), 코퍼스 회귀 하네스와 매칭 실패율 측정, A1-1·A1-3·A2-3·A3-6 결정 |

전제와 재산정 시점

- M1 처럼 패키지별 병렬 세션을 계속 쓴다는 전제다. 직렬로 진행하면 M1·M3 가 각각 1~2주 늘 수 있다.
- 완충 기간은 두지 않았다. M1 종료 시 코퍼스 매칭 실패율과 원본 연결 난이도로 M2 이후를 다시 산정한다.
- 일정은 서버 개발 기준이다. Windows Chrome 수동 확인(3절)은 각 마일스톤 끝에 사용자 확인으로 둔다.
